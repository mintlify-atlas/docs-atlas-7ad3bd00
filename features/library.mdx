The library is the heart of wi-mod. Every mod you add — whether fetched from Nexus Mods, Modrinth, CurseForge, or entered manually — lands in a local SQLite database file (`wi-mod.sqlite`) stored alongside the application. There are no accounts, no cloud sync, and no external dependencies: your library is yours, on your machine. From a single unified view you can browse mods across every game and platform, annotate them with personal notes, assign them to modpacks, and control their load order.

## Mod fields

Each mod record carries the following fields. Fields marked **User-editable** can be changed from the library view or via the API; all others are populated automatically when a mod is fetched from a platform.

| Field | Type | Description |
|---|---|---|
| `id` | `string` | Internal UUID hex (32 chars) generated by wi-mod |
| `name` | `string` | Display name of the mod |
| `platform` | `string` | Source platform: `Nexus`, `Modrinth`, `CurseForge`, `Steam Workshop`, `ModDB`, or `Independiente` |
| `gameDomain` | `string` | Machine-readable game identifier (e.g. `skyrimspecialedition`, `minecraft`) |
| `gameName` | `string` | Human-readable game name (e.g. `The Elder Scrolls V: Skyrim Special Edition`) |
| `modId` | `number \| null` | Numeric mod ID on Nexus Mods; `null` for other platforms |
| `version` | `string` | Installed version string |
| `author` | `string` | Mod author name |
| `category` | `string` | Category label (e.g. `Gameplay`, `Models and Textures`) |
| `summary` | `string` | Short description, sourced from the platform |
| `status` | `string` | Combination of `got` (downloaded) and `in` (active); empty means tracked only |
| `notes` | `string` | **User-editable** — free-form personal notes |
| `techNotes` | `string` | **User-editable** — technical installation notes (up to 4 000 chars) |
| `compatNotes` | `string` | **User-editable** — compatibility notes for other mods (up to 4 000 chars) |
| `emoji` | `string` | **User-editable** — short emoji label for quick visual scanning (up to 12 chars) |
| `skill` | `string` | **User-editable** — skill or difficulty tag (up to 80 chars) |
| `rule` | `string` | **User-editable** — load rule tag (up to 80 chars) |
| `priority` | `number` | Integer load-order priority within a game; higher number loads last and wins conflicts |
| `modpackId` | `string` | ID of the modpack this mod belongs to (empty if unassigned) |
| `modpackCategoryId` | `string` | ID of the sub-category within the modpack |
| `modpackNotes` | `string` | **User-editable** — pack-specific annotation (up to 4 000 chars) |
| `files` | `array` | Local file records with `storedAs` path, `size`, and `name` |
| `addedAt` | `string` | ISO 8601 timestamp when the mod was added |
| `fetchedAt` | `string \| null` | ISO 8601 timestamp of the last successful platform fetch |

## Status flags

A mod's `status` field is a `+`-delimited combination of two independent flags:

- **`got`** — the mod archive has been downloaded and is stored locally.
- **`in`** — the mod is active and will be included when deploying to the game's Data folder.

A mod that is tracked but not yet downloaded has an empty `status`. A downloaded but inactive mod has `status: "got"`. An active mod has `status: "got+in"`. Only mods with the `in` flag are scanned for conflicts and deployed to the game.

<Note>
  Toggling a mod inactive (removing the `in` flag) renames its stored archive file with a `.disabled` suffix, preventing accidental deployment. Re-activating it restores the original filename.
</Note>

## Filtering and sorting

The library view supports filtering along multiple dimensions simultaneously:

- **Game** — show only mods for a selected `gameDomain`
- **Platform** — filter by source platform (Nexus, Modrinth, CurseForge, etc.)
- **Category** — filter by category label
- **Modpack** — show only mods assigned to a specific modpack
- **Active / inactive** — show only `in` mods or only inactive ones

Mods can be sorted by name, priority, date added, or download count. The priority field controls load order within a game: mods are sorted 1 … N, with the highest number loaded last (and therefore winning file conflicts).

## Conflict detection

wi-mod automatically scans the zip archives of every **active** mod in the same game and compares the internal file paths. When two active mods contain the same file path, they conflict. The conflict result is annotated on each mod in the `GET /api/library` response under the `conflict` key:

```json
"conflict": {
  "wins": 2,
  "loses": 0,
  "overwrites": ["SMIM", "Landscape Overhaul"],
  "overwrittenBy": []
}
```

- **`overwrites`** — mods this mod overrides (it has a higher priority)
- **`overwrittenBy`** — mods that override this mod (they have a higher priority)

The mod with the **higher priority number** wins: it is deployed last and its file replaces the one from any lower-priority mod that shares the same path.

## Bulk operations

Select multiple mods in the library view to apply operations in bulk:

- **Assign category** — set the same category on all selected mods (`POST /api/mods/assign` with `category`)
- **Assign platform** — reassign the platform label (`POST /api/mods/assign` with `platform`)
- **Assign modpack** — move selected mods into a modpack and optional sub-category (`POST /api/mods/assign` with `modpackId` / `modpackCategoryId`)
- **Toggle active** — enable or disable all selected mods at once (`POST /api/mods/active` with `ids` and `active`)
- **Clone** — duplicate selected mods as separate entries (`POST /api/mods/clone`)
- **Reorder** — drag to set a new `packOrder` within a modpack (`POST /api/mods/order`)

<Note>
  Bulk activate/deactivate only affects mods that have already been downloaded (those with `got` in their status). Mods that are tracked but not yet downloaded are skipped silently.
</Note>

## API endpoint reference

| Method | Path | Description |
|---|---|---|
| `GET` | `/api/library` | Returns mods, modpacks, catalog, language, theme, sources, and API key flags |
| `POST` | `/api/mods` | Add a new mod (accepts a Nexus/Modrinth/CurseForge URL or manual fields) |
| `PATCH` | `/api/mods/:id` | Update fields on a single mod |
| `DELETE` | `/api/mods/:id` | Remove a mod and delete its local files |
| `POST` | `/api/mods/assign` | Bulk-assign category, platform, or modpack to multiple mods |
| `POST` | `/api/mods/active` | Bulk-toggle active status; optionally targets all mods in a modpack via `modpackId` |
| `POST` | `/api/mods/order` | Reorder mods within a modpack by providing a new ordered list of IDs |
| `POST` | `/api/mods/clone` | Duplicate one or more mods (files are not copied) |

The `GET /api/library` response is the primary data payload for the frontend. It returns:

```json
{
  "mods": [...],
  "modpacks": [...],
  "catalog": { "platforms": [], "games": [], "categories": [], "skills": [], "rules": [] },
  "language": "en",
  "theme": "nexus",
  "sources": { "minecraft": ["Modrinth", "CurseForge", "Independiente"], ... },
  "keys": { "nexus": true, "curseforge": false, "steam": false, "rawg": false },
  "packsDir": "/path/to/packs"
}
```
